# Shorts Inserter

Десктопное приложение на Electron, которое пакетно монтирует видео без DaVinci Resolve.

Для каждого видео из выбранной папки приложение:

1. берёт первые **X%** исходника (по умолчанию 90%);
2. вставляет следом выбранный ролик **Shorts**;
3. добавляет оставшийся хвост исходника;
4. при желании собирает **split-screen**: слева основной ролик, справа второе видео крупным планом;
5. при желании накладывает **оверлей** поверх всего хронометража;
6. сохраняет результат в `esN.mov` — `es1.mov`, `es2.mov`, `es3.mov` и так далее.

FFmpeg и FFprobe поставляются вместе с приложением (`ffmpeg-static`, `ffprobe-static`) — ставить
их в систему не нужно.

## Скачать для Windows

Готовые сборки лежат на [странице релизов](https://github.com/lolkiper/html/releases/latest):

- `Shorts Inserter Setup <версия>.exe` — установщик;
- `Shorts Inserter <версия>.exe` — portable-версия, запускается без установки.

Сборку делает GitHub Actions на Windows-раннере (`.github/workflows/build-windows.yml`),
новый релиз выходит при появлении тега `v*`.

## Запуск из исходников

```bash
npm install
npm start
```

## Сборка под Windows

```bash
npm run dist            # установщик NSIS + portable-версия в папке dist/
npm run dist:portable   # только portable .exe
```

Бинарники FFmpeg распаковываются из `app.asar` (`asarUnpack`), поэтому собранное приложение
работает на машине без установленного FFmpeg.

## Проверка конвейера без интерфейса

```bash
npm run smoke
```

Скрипт генерирует тестовые ролики, прогоняет их через `processor.js` и проверяет порядок
сегментов по цвету кадров, зацикливание оверлея, длительность и разрешение результата,
устойчивость к битому файлу, остановку обработки и экспорт в ProRes.

## Как пользоваться

| Поле | Что делает |
| --- | --- |
| Папка с исходными видео | все видеофайлы папки попадают в очередь (без вложенных папок) |
| Файл Shorts | ролик, который вставляется в середину каждого исходника |
| Разделить экран | включает split-screen: слева основной ролик, справа второе видео |
| Использовать оверлей | накладывает выбранное видео поверх всего результата, включая сплит |
| Непрозрачность оверлея | 5–100%, по умолчанию 100% |
| Папка для сохранения | сюда пишутся `es1.mov`, `es2.mov`, … |
| Размер итогового кадра | 1080×1080 (по умолчанию), 1080×1920, 1920×1080 или как у исходника |
| Если пропорции не совпадают | заполнить кадр с обрезкой (по умолчанию) или вписать целиком с полями |
| Процент обрезки | 50–99, точка вставки Shorts |
| Кодек результата | H.264 (по умолчанию), H.265 или ProRes 422 HQ |

Под каждым полем сразу показывается, что именно выбрано: количество найденных видео,
разрешение, длительность и наличие звука. Настройки запоминаются между запусками.

Во время работы видно прогресс текущего файла и всей очереди, статус с именем ролика и
живой лог. Кнопка «Остановить» прерывает обработку и удаляет недописанный файл.

## Split-screen

Кадр делится на две половины: слева идёт основной сюжет, справа — крупный план,
как в вертикальных роликах TikTok и Shorts.

Каждая половина — это окно в «слой»: видео увеличивается на **зум**, центр слоя сдвигается
на **сдвиг по X**, и в кадр попадает только та часть слоя, которая приходится на свою половину.
Логика та же, что у Position X и Zoom в монтажной программе.

| Настройка | По умолчанию | Что делает |
| --- | --- | --- |
| Ширина левой части | 50% | где проходит граница между половинами |
| Мягкость границы | 8 px | 0 — чёткий стык, больше — плавное перетекание |
| Левая часть, увеличение | 1.00× | без увеличения, как есть |
| Левая часть, сдвиг по X | −25% | это −480 px при ширине 1920: в левую половину попадает центр кадра |
| Правая часть, увеличение | 1.80× | крупный план |
| Правая часть, сдвиг по X | +25% | второе видео уезжает вправо и обрезается слева |

Сдвиги заданы в процентах от ширины кадра, поэтому настройки не зависят ни от разрешения
исходников, ни от выбранного размера кадра. При делении 50/50 сдвиг −25% ровно центрирует
содержимое в своей половине.

Второе видео живёт по тем же правилам, что и оверлей: короткое зацикливается, длинное
обрезается по длине результата. Звук берётся только из основного ролика.

## Поведение в деталях

- **Размер кадра** задаётся настройкой: по умолчанию 1080×1080. Исходник и Shorts приводятся
  к этому размеру с сохранением пропорций — лишнее обрезается по краям либо, если выбрано
  «вписать целиком», добавляются чёрные поля. Fps берётся из исходника, поворот из метаданных
  учитывается.
- **Оверлей короче результата** — зацикливается (`-stream_loop -1`); **длиннее** — обрезается
  по длине результата (`overlay=shortest=1`). Масштабируется с заполнением кадра.
- **Нет звука** в исходнике или Shorts — соответствующий сегмент дополняется тишиной, чтобы
  склейка не рассыпалась.
- **Ошибка на одном ролике** пишется в лог, очередь продолжается, недописанный файл удаляется.
- Если папка результата совпадает с папкой исходников, ранее созданные `esN.mov` в очередь
  не попадают.

## Структура

| Файл | Назначение |
| --- | --- |
| `main.js` | процесс Electron: окно, системные диалоги, IPC, управление очередью |
| `preload.js` | мост `window.api` между интерфейсом и main (contextIsolation) |
| `processor.js` | работа с FFmpeg: метаданные, граф фильтров, пакетная обработка |
| `renderer.js` | логика интерфейса, прогресс, лог, сохранение настроек |
| `index.html`, `styles.css` | вёрстка и тёмная тема |
| `scripts/smoke-test.js` | сквозная проверка конвейера |

## Требования

Node.js 18+ для сборки. Собранное приложение — Windows 10/11 x64 (также собирается под macOS и
Linux).

# LDPlayer Visual UI Tester

Windows-приложение для автоматического тестирования интерфейса Android-приложений,
запущенных в **LDPlayer**. Это визуальный движок автоматизации, а не проигрыватель
макросов: программа смотрит на окно эмулятора, определяет, какой экран показан
сейчас, выполняет действие, закреплённое за этим экраном, проверяет результат и
только потом выбирает следующую ветку.

```
АНАЛИЗ ЭКРАНА → ОПРЕДЕЛЕНИЕ СОСТОЯНИЯ → ДЕЙСТВИЕ → ПРОВЕРКА РЕЗУЛЬТАТА → ВЫБОР СЛЕДУЮЩЕЙ ВЕТКИ
```

Кадры не попадают на диск:

```
LDPlayer → захват → ОЗУ → OpenCV / OCR → результат → освобождение памяти
```

Папки `screenshots/`, `temp/`, `cache_images/` не создаются никогда, изображения не
пишутся в журнал. На диске лежат только эталонные изображения, которые вы добавили
сами.

Английская версия документации: [README.md](README.md).

## Установка

Нужен Python 3.11 или новее. Скачайте его с
[python.org](https://www.python.org/downloads/windows/) и в установщике отметьте
**Add python.exe to PATH**.

1. Скачайте архив проекта и распакуйте (не в синхронизируемую папку OneDrive).
2. Двойной клик по **`run.bat`** — он создаст окружение `.venv`, поставит
   зависимости при первом запуске и откроет программу.

Вручную то же самое:

```bat
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python main.py
```

OCR (условия по тексту и числам) ставится отдельно, потому что скачивается долго:

```bat
pip install -r requirements-ocr.txt
```

Без OCR программа полностью работает — просто условия по тексту и числам не
срабатывают, и в журнал пишется предупреждение.

## Первый сценарий

1. Запустите нужный экземпляр LDPlayer.
2. В программе нажмите **Обновить**, выберите экземпляр в списке и нажмите
   **Выбрать**. Если окно не нашлось (нестандартный заголовок) — **Область
   экрана...** и задайте прямоугольник вручную.
3. **Сохраните** проект: эталонные изображения пишутся на диск только после этого.
   Если при захвате открылось чёрное окно — кадр не снялся (часто у LDPlayer
   из‑за GPU). Отодвиньте редактор, не сворачивайте эмулятор. Если снова чёрный:
   **Настройки движка** → **Захват** → `mss`.
4. **LOAD TEST DATA** — текстовый файл, одна учётка на строку:
   `email|password` или `email:password`. Битые строки попадают в INVALID.
   Пароли остаются в ОЗУ и не пишутся в проект и журнал.
5. **+ ЗАПИСАТЬ МАКРОС (MACRO_1)**. В поле email введите `{{EMAIL}}`. Пароль
   на этом этапе не вводите.
6. **ЗАХВАТИТЬ СОСТОЯНИЕ УСПЕХА / ОШИБКИ** для VERIFY_1 — маленький элемент,
   не весь экран.
7. Так же запишите MACRO_2, MACRO_3 (`{{PASSWORD}}` только здесь), MACRO_4
   и эталоны VERIFY_2..4.
8. Если появляется bot-check / подтверждение — захватите его как
   **MANUAL_ACTION_REQUIRED**. Программа **не обходит** защиту: останавливается
   и ждёт **Продолжить**.
9. **СТАРТ (F8)**. Каждый этап: MACRO → пауза → визуальная проверка.
   Только `VERIFY_n_SUCCESS` открывает следующий макрос. Ошибка — FAILED,
   RESET, следующая запись. Неизвестно — повтор, затем пропуск записи.

```
ЗАГРУЗИТЬ ЗАПИСЬ → MACRO_1 → VERIFY_1 → MACRO_2 → VERIFY_2
                → MACRO_3 → VERIFY_3 → MACRO_4 → VERIFY_4 → УСПЕХ → СЛЕДУЮЩАЯ
```

## Запись макроса

Кнопка **+ ЗАПИСАТЬ МАКРОС (MACRO_1)** — большая зелёная, сразу под заголовком
**МАКРОС**. MACRO_2 / MACRO_3 / MACRO_4 пишутся своими кнопками. Во вкладке
**Пайплайн** у каждого этапа есть **Запись / Изменить / Прогон**. Рекордер:

1. Нажмите **Начать запись**.
2. Выполните нужную комбинацию в окне LDPlayer.
3. Нажмите **F10** (или кнопку **Остановить**).
4. **Использовать запись** — шаги добавятся в состояние или в сценарий.

Что происходит с записью:

| Что вы сделали | Что записалось |
|---|---|
| нажатие и отпускание на одном месте | Левый клик |
| два быстрых клика подряд | Двойной клик |
| нажали в одном месте, отпустили далеко | Перетаскивание |
| Ctrl+A и подобное | Горячие клавиши |
| набрали текст | одно действие «Ввести текст» |
| пауза между действиями | «Пауза» на это же время |
| действия вне окна эмулятора | пропускаются |

Записываются не «слепые» координаты экрана: каждая позиция хранится
относительно окна (в долях 0..1), поэтому запись продолжает работать после
перемещения и изменения размера эмулятора.

Галочка **Привязывать клики к изображениям** делает макрос по-настоящему
визуальным: в момент клика запоминается небольшой фрагмент того, по чему вы
щёлкнули, он сохраняется как эталонное изображение проекта, и при проигрывании
движок ищет этот элемент и щёлкает по нему, а не по координате.

### Разные комбинации для разных экранов

Именно то, о чём обычно спрашивают: «если появилось такое окно — одна
комбинация, если другое — другая».

1. Создайте состояние `ЭКРАН_НАГРАДЫ` с эталонным изображением этого экрана и
   запишите в него комбинацию А (**Записать...** в редакторе состояния).
2. Создайте состояние `ЭКРАН_ОШИБКИ` и запишите в него комбинацию Б.
3. В сценарии соберите:

```
НАЧАЛО
↓
АНАЛИЗ ЭКРАНА
↓
ЕСЛИ СОСТОЯНИЕ ЭКРАН_НАГРАДЫ обнаружено
├── ДА → СОСТОЯНИЕ ЭКРАН_НАГРАДЫ (выполняет комбинацию А) → ПРОВЕРКА
├── ИНАЧЕ ЕСЛИ СОСТОЯНИЕ ЭКРАН_ОШИБКИ обнаружено → СОСТОЯНИЕ ЭКРАН_ОШИБКИ (комбинация Б)
└── ИНАЧЕ → ПАУЗА 1 с → ПОВТОР (анализируем снова)
```

Шаг **ДОБАВИТЬ СОСТОЯНИЕ** в сценарии выполняет действия состояния вместе с его
проверкой результата, повторами и откатом. Можно и без сценария: режим движка
**states** сам крутит таблицу состояний и для каждого распознанного экрана
выполняет его комбинацию.

## Распознавание

| Способ | Условие | Примечание |
|---|---|---|
| Сравнение с эталоном | «Эталонное изображение видно» | несколько масштабов, прозрачность, своя область, возвращает позицию элемента |
| Особые точки (ORB) | режим `feature` | терпимо к масштабу и небольшому повороту |
| Гистограмма | режим `histogram` | «экран в целом похож на этот» |
| Текст (OCR) | «Текст виден» | подстрока, строка целиком или регулярное выражение |
| Числа (OCR) | «Сравнение числа» | `>=`, `<` и т.д. с распознанным числом |
| Цвет пикселя | «Цвет пикселя» | нормированная позиция и допуск |
| Доля цвета | «Цвет присутствует в области» | например, кнопка позеленела |
| Разница кадров | «Экран изменился» | любое визуальное изменение с прошлого цикла |

У каждого результата есть уверенность, а у найденного — прямоугольник, поэтому
действие может щёлкнуть **центр того, что распознано**, а не фиксированную точку.

## Состояния

| Поле | Смысл |
|---|---|
| имя, описание | например, `ЭКРАН_ОШИБКИ` |
| эталонные изображения | одно или несколько, у каждого своя уверенность и область |
| условие | дополнительная логика (И с изображениями): OCR, цвет, переменные, И/ИЛИ/НЕ |
| изображения должны совпасть | «любое» или «все» |
| уверенность | порог, при котором состояние считается обнаруженным |
| таймаут | сколько ждать это состояние |
| число повторов и пауза | сколько раз повторить действия, если проверка не прошла |
| задержка | минимальная пауза перед повторным срабатыванием |
| действия | что делать при обнаружении (можно записать макросом) |
| ожидаемый результат | состояние или условие, которое должно появиться после действий |
| таймаут проверки | сколько ждать этот результат |
| откат | состояние при исчерпании повторов или `STOP` |
| следующее состояние | что ждать в следующем цикле |
| конечное | успешный прогон здесь завершается |

Состояние `UNKNOWN` — настоящее: если задать ему действия, они выполняются, когда
ничего не распознано (например, «нажать Назад и проанализировать снова»).

## Логика сценария

Поддерживаются `ЕСЛИ`, `ИНАЧЕ ЕСЛИ`, `ИНАЧЕ`, `И`, `ИЛИ`, `НЕ`, `ПАУЗА`,
`ЖДАТЬ ПОКА`, `ПОВТОР`, таймауты, `ПРОВЕРКА`, `ЦИКЛ`, `СТОП`.

Действия: подвести мышь, левый / двойной / правый клик, перетаскивание, нажать
клавишу, горячие клавиши, ввести текст, пауза, ждать условие, проверить,
повторить, стоп, задать переменную, запись в журнал.

Цель клика — либо позиция внутри окна (в долях или точных пикселях), либо позиция
чего-то распознанного: последнее совпадение, эталонное изображение, найденный
текст или элемент, по которому опознано текущее состояние.

## Проверка результата

После действий движок захватывает **новый** кадр, анализирует его, определяет
состояние, сравнивает с ожидаемым и записывает результат:

```
[19:30:01] Обнаружено состояние: ЭКРАН_А, уверенность=0.94
[19:30:01] Клик в окне (179,250) [элемент состояния «ЭКРАН_А», уверенность=0.94]
[19:30:02] Начата проверка
[19:30:02] Проверка: УСПЕХ
```

Если ожидаемый экран не появился:

```
[19:30:05] Проверка: ОШИБКА (ожидалось ЭКРАН_Б, обнаружено ЭКРАН_А)
[19:30:05] Повтор 1/3
```

## Безопасность

- **F8** — старт / пауза / продолжить, **F9** — аварийный стоп. В Windows обе
  клавиши регистрируются глобально и работают, когда активен LDPlayer.
- Перед **каждым** действием проверяется: окно существует, не свёрнуто и имеет
  рабочий размер; точка находится внутри окна; уверенность не ниже порога;
  распознавание не является неоднозначным (два состояния в пределах порога
  неоднозначности отменяют действие, а не «угадывают»).
- Задержки по цели и по состоянию, общий предел действий в минуту.
- Предохранитель PyAutoGUI: если увести курсор в угол экрана, прогон прервётся.
- **Пробный прогон** — полный анализ без отправки ввода.
- Текст, помеченный как чувствительный, не попадает в журнал (пишется только его
  длина) и может подставляться из переменной, чтобы не храниться в файле проекта.
- В журнал никогда не попадают изображения.

## Хранение

```
МойТест.ldproj/
    project.json        состояния, сценарий, настройки
    references/         только эталонные изображения, добавленные вами
```

Кадры остаются в ОЗУ. Кнопка **Проверить проект** в том числе убеждается, что
рядом с проектом не появилось сохранённых кадров.

## Командная строка

```bat
run.bat --list-instances                                  :: список окон LDPlayer
run.bat --project МойТест.ldproj --print-workflow         :: показать дерево сценария
run.bat --project МойТест.ldproj --analyze                :: один цикл распознавания
run.bat --project МойТест.ldproj --run                    :: прогон без интерфейса
run.bat --project МойТест.ldproj --run --dry-run --max-cycles 5
run.bat --project МойТест.ldproj --run --region 120,90,360,560
```

Код выхода `0`, если ни один шаг не упал, иначе `1` — сценарий можно использовать
как проверку в CI. Полезные флаги: `--instance` (индекс, hwnd или часть
заголовка), `--mode workflow|states`, `--duration`, `--log-file`, `--lang`.

## Язык интерфейса

По умолчанию интерфейс русский. Переключатель **Язык** в верхней панели меняет
язык сразу — вместе с журналом, схемой сценария и описаниями шагов. Выбор
сохраняется в проекте; в командной строке используйте `--lang ru|en`.

## Архитектура

| Модуль | Ответственность |
|---|---|
| `main.py` | командная строка, прогон без интерфейса, запуск GUI |
| `gui.py` | редактор сценария, редактор состояний, рекордер, журнал, управление |
| `ldplayer.py` | поиск окон, отслеживание геометрии, пересчёт координат |
| `screen_capture.py` | захват только в ОЗУ (PrintWindow / BitBlt, запасной `mss`) |
| `vision.py` | сравнение через OpenCV, области, цвет и разница кадров |
| `ocr.py` | PaddleOCR / Tesseract, поиск текста и чисел |
| `state_machine.py` | описания состояний, определитель, автономный движок |
| `conditions.py` | предикаты ЕСЛИ / И / ИЛИ / НЕ по текущему кадру |
| `actions.py` | действия, цели, проверка результата |
| `workflow.py` | дерево сценария, выполнение, отрисовка схемы |
| `recorder.py` | запись реальных действий и сборка их в шаги |
| `mouse.py`, `keyboard.py` | ввод относительно окна, глобальные горячие клавиши |
| `safety.py` | проверки перед действием, задержки, старт/пауза/стоп |
| `project.py` | хранение проекта и эталонных изображений |
| `logger.py` | текстовый журнал с сокрытием чувствительных данных |
| `i18n.py` | переводы интерфейса и журнала |

Тесты: `pip install -r requirements-dev.txt` и `python -m pytest -q`.
